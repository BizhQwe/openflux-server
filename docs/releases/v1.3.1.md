# OpenFlux Server v1.3.1

Обновление OpenFlux Server v1.3.1 с нативной поддержкой роутеров (Keenetic / OpenWrt с Entware), гибким выбором портов и безопасным управлением брандмауэром:

### 🚀 Что нового:

1. **Нативная поддержка роутеров с Entware (Keenetic / OpenWrt)**:
   - В установщик добавлен флаг `--entware` и автоопределение окружения без systemd при наличии `/opt/etc/init.d`.
   - Автоматическая регистрация SysVinit-службы `/opt/etc/init.d/S99openflux` с командами `start`, `stop`, `restart`, `status`.
   - Оптимизация памяти под аппаратные ограничения роутеров: автоматическая настройка `GOMEMLIMIT=192MiB` и `GOGC=50`.
   - Регистрация команды CLI в `/opt/bin/openflux` с прямой поддержкой управления службой Entware.
   - Скрипт `scripts/install-entware.sh` стал легковесным загрузчиком с проверкой SHA-256.

2. **Выбор порта веб-панели в установщике**:
   - Мастер установки теперь интерактивно запрашивает порт веб-панели (по умолчанию 5000) или принимает флаг `--port <число>`.
   - Поддерживается проверка занятости: если стандартный порт занят, установщик предлагает свободный адрес.

3. **Безопасная изоляция брандмауэра (Firewall)**:
   - Установщик запрашивает подтверждение на открытие порта в брандмауэре.
   - Сетевой экран управляет **исключительно** портом самой веб-панели. Порты 80, 443 и порты сторонних служб (например, 3x-ui, Xray, Docker) больше никогда не затрагиваются.
   - В `firewalld` исключен вызов `--reload`, который приводил к сбросу runtime-правил других приложений.
   - В `iptables` / `ip6tables` все правила OpenFlux маркируются комментарием `OpenFlux Panel & Web` и вставляются в начало цепочки INPUT (`-I INPUT 1`), что гарантирует корректную работу на Keenetic с политикой `INPUT DROP`.

4. **Интерактивный деинсталлятор (`openflux uninstall`)**:
   - Перед удалением CLI считывает фактический порт панели и запрашивает, нужно ли закрыть этот порт в брандмауэре.
   - При отказе порт остаётся открытым, при подтверждении закрывается только порт панели.
